# Coding Agent 原理与实践：imp 开发手记

## 目标、读者与作者背景

本系列有两个同等重要的目标：记录作者开发 imp 实际做了哪些工作；让有 Coding Agent 使用经验的读者理解开发这类系统需要解决哪些问题。

作者提供的背景：模型能力提升，harness 让模型参与实际工作；现有产品在使用门槛、过程可见性、设计与完成度上未满足自己的偏好。pi 的简洁和自定义能力吸引了作者，因此参考 pi，从零实现自己的编程助手，既学习 Agent 的原理，也希望用它解决真实问题。

写作时保留作者的观点与声音。对 Claude Code、Codex 和国产产品的评价明确属于个人使用体验，不扩写成普遍事实；显示模型已返回的信息，不等于能够取得模型未提供的内部推理。

## 组织原则

- 章节按理解与实现的依赖关系组织，以最小执行闭环为起点。
- 每章内部按该模块的真实开发历史讲演进、取舍、问题与验证。
- 00 给整体架构和开发时间线；01 用两个抽象接口串起完整循环；02、03 再分别拆开模型接入与工具实现。
- 04 讨论本次请求携带什么；05 讨论历史如何保存和恢复，明确上下文与持久化的区别。
- 权限与测试从相关模块开始出现，07 和 10 专章系统整理。
- 不按“核心程度”硬排序，也不将提交日志直接拆成博客。

## 单章模板

1. 模块解决的问题：具体任务或真实故障。
2. 在系统中的位置：输入、输出、与哪些模块交互。
3. 原理与最小伪代码：先实现最短的正常路径。
4. imp 实际做的工作：文件结构、步骤、选择与替代方案。
5. 工程演进：每个新增机制对应一个问题，说明改前与改后。
6. 验证、局限与小结：测试/实际执行证据、未解决部分、下一章。

每篇明确区分通用需求、imp 的实现选择与尚未验证的假设。示意任务和预设数据标明“模拟”；真实对话、性能、测试数与开发日期必须有记录支持。代码链接优先用已确认存在的固定提交。

## 展示与技术约定

采用 MDX，保留 Markdown 正文，组件实现与文章分离。继续使用现有 Astro 和静态部署，不增加在线模型调用或新的前端框架。

### 视觉方向：可阅读的工程手记

- 连贯的单栏正文；图示只出现在解释结构或状态的位置。
- 图示使用局部色板：浅灰画布 `#f4f6fa`、白纸 `#ffffff`、石墨文字 `#243244`、辅助文字 `#59677b`、执行蓝 `#2855bd`、结果绿 `#087c6e`；深色主题提供对应颜色。
- 系统中文无衬线字体用于正文和注释，等宽字体只用于代码、哈希等精确信息。
- 架构图用边界表达职责，蓝色突出执行中心，绿色用于工具与环境反馈；时间线只表达真实时间顺序。
- 不增加自动播放动画。手机上结构图转为纵向，正文和图注不依赖悬停。
- 静态文字承担完整解释；交互只帮助观察变化，不把核心结论藏在点击或视频中。

已评估课程落地页、仪表盘和工程手记三种方向：选择工程手记，因为本系列以长文解释和真实开发证据为中心。仅调整本系列的展示组件，不修改博客全局主题。

### 分三层制作

1. 正文、伪代码、表格和静态结构图先完成；图示保持可选择、可检索的文字。
2. 对循环、压缩、分支等动态机制，按文章需要制作一个目标明确的交互组件。
3. 真实日志、diff、提交和录屏作为证据；长内容提供摘要、说明或文字稿。

00 使用四个静态 Astro 组件：`AgentArchitecture`、`TaskOverview`、`DevelopmentTimeline`、`SeriesDirectory`。采用语义 HTML 与 CSS 实现响应式图示，避免把手机上的文字缩进一张过宽的图。暂无必要引入 Mermaid 运行时；后续复杂时序图可评估构建时生成 SVG。

共用色板放在 `src/components/series/series-visual.css`，选择器限定在 `.series-visual`。后续交互优先用组件中的小段脚本，需要复杂状态时再评估框架。
