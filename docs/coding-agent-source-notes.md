# 后续章节素材

由旧版 00 中的细节整理而来。以下是写作素材，不是已完成文章。

## 01：执行循环

保留的最小流程：用户消息进入历史 → 发起模型请求 → 记录回复 → 如有工具请求则执行并记录结果 → 再次调用模型；没有工具请求则本轮结束。中断、错误和轮数上限在最小版本之后逐步补充。

示意任务：“求和函数输入 `[1, 2, 3]` 却返回 `"123"`”。用预设步骤演示搜索、读取、把累加器初值从空字符串改为数字零、运行测试。必须标明是假设示意，不能当成 imp 的真实验收记录。

来源：`src/core/loop.ts`、`test/loop.test.ts`、`test/loop-hooks.test.ts`。

## 03：工具请求与错误反馈

展示一个简化的 `read` 请求：工具名、文件路径；对照本地参数校验、执行和返回结果。模型说“准备运行测试”不是执行证据，需要检查工具记录、退出码与实际输出。

`edit` 的旧文本匹配为 0 或多处时应返回明确错误，引导模型重新读取或扩大匹配范围。可通过三种输入演示失败反馈如何改变下一步。

来源：`src/core/tools/types.ts`、`src/core/tools/edit.ts`、`test/edit-write.test.ts`。

## 05：中断后会话无法恢复

真实问题：模型工具请求已经持久化，但运行在工具结果写入之前结束；恢复后历史里出现未配对的调用，导致后续模型请求失败。

修复：在中断和达到轮数上限等退出路径，为未执行的工具补上明确结果，使请求与结果配对完整。不将这个修复描述为覆盖所有强制终止、磁盘故障或断电情形。

已核对提交：[9b432c6](https://github.com/FishInSalt/imp/commit/9b432c61b36c9eb83a5ee516e9272a94fdef64ba)。后续绘制“保存调用 → 中断 → 恢复请求失败”的时序图，并引用相关回归测试。
